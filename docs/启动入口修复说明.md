# Windows 启动入口修复说明

修复日期：2026-11-16。本修正版保留之前的技术 PDF 和业务代码，只修复两个 Windows 启动脚本的编码兼容问题。

## 原因与修改

外层脚本使用 UTF-8 中文文件名，但 Windows 默认代码页为 936；在切换代码页前调用下一层中文文件名会失败。外层没有成功运行内层启动器，因此双击可能一闪而过，网页端口没有启动。

外层现在先执行 `chcp 65001`，两个 `.cmd` 文件统一采用 Windows CRLF 换行；内层以 `python -X utf8` 运行启动器，统一中文输出编码。没有修改系统 PATH、账号数据库、研究数据库、API 配置或任何交易规则。

## 实际验证

- 修复前：在代码页 936 下运行入口并传入 `--help`，报命令无法识别，退出码 1。
- 修复后：同一入口能够显示 Python 参数帮助，中文正常，退出码 0。
- 使用修复后的入口启动本机服务后，`http://127.0.0.1:3001/` 返回 HTTP 200，健康接口返回 `evidence-desk-contest`。

原材料包没有被覆盖。新压缩包名称带“启动修复”，源码中的 SHA-256 清单和材料总包清单均已按修复后的文件重新生成。技术 PDF 的自动化测试数量是当时记录的基线，本次入口检查为上述独立手动验证，不冒充新增自动化用例。

本机直接运行请在文件资源管理器中双击 `contest-edition/启动智慧交易助手.cmd`。首次安装依赖仍按 README 进行；聊天内的文件链接可能只打开文件预览，不一定执行脚本。
