副标题：多席位策略研究与交易复盘

文档日期：2026年11月17日。适用对象：本次准备提交的最新版源码；前端包版本为0.3.1，详细能力以本说明、源码及对应验收记录为准。本文用于导出不超过30页的参赛技术PDF，提交前仍须核对实际导出页数。

## 1 项目概述

### 1.1 解决的问题

行情研究经常混合三类不同事实：事前是否有依据，实际是否满足成交条件，以及事后价格是否上涨。通用对话又容易把新闻解释当成公司受益证明，或者在知道后续走势后修改原有判断。只展示成功案例和一条收益曲线，无法回答为什么选择这只股票、为什么保留现金、为何没有成交、失败属于数据缺口还是执行限制。

智慧交易助手把观察、预案、风控、账本与回放拆开：用截止前证据形成判断，用独立规则决定是否允许模拟，保存当时的规则和参数，再查看后续行情。新闻页提供全球事件的空间入口，但新闻关联不自动成为买卖指令。系统允许明确观望、拒单、证据不足及未平仓，不以强行产生交易作为功能完成标准。

### 1.2 当前成果与定位

正式工作台包含研究台、复盘台、审计台和全球新闻四个页面。主区提供三个各自初始10万元的独立纸面账户，支持全市场自主扫描、模拟订单、持仓与收益查看；折叠工具保留单股研究、证据冻结和研究档案。基础席位支持真实模型协议接入；另外两个席位执行独立本地规则。全球新闻运行期间每5分钟检查白名单来源，可主动调用模型分析一条新闻的板块关联。

本机已下载3,049只沪深主板股票的真实日线，固定决策截止为2026-11-12，历史演示日为2026-11-13。这不是2026-11-17实时行情。原始行情、财报PDF及私人数据库不随公开源码自动发布；评审环境需要按授权条件准备资料或显式导入，不能用合成数据冒充下载成功。旧合成案例仍用于隔离测试与已有档案兼容，不再作为正式默认股票演示。

## 2 需求分析与验收边界

### 2.1 使用任务

目标使用者是需要核对策略规则、观察模型输出和进行交易复盘的个人研究者，也适用于AI工程演示。核心路径是：查看行情及新闻，选择研究方式，确认规则及缺项，主动启用模拟，检查买卖和账本，最后按原有证据解释结果。三席位共享股票目录，但证据类型、判断标准和执行纪律不能混用。

| 需求 | 对应实现与验收原则 |
| --- | --- |
| 不再只看单只股票 | 按股票代码顺序扫描本地符合范围的全市场目录，不按未来收益倒排。 |
| 知道买了什么、多少钱 | 按账号、历史/实时模式、席位保存完整订单、持仓、费用和现金变动。 |
| 三个页面各有职责 | 研究台负责操作及账户；复盘台负责统计和回放；审计台负责判断原因和规则。 |
| AI有用且受约束 | 单股基础研究采用工具调用与JSON预案；新闻AI只分析用户主动选择的一条。 |
| 保留原始判断 | 冻结证据、参数和规则指纹；新研究新建记录，不覆盖旧档案或重算旧订单。 |
| 显示数据不足 | 来源参考不等于严格核验，缺失财报、竞价或证券状态时保留现金。 |
| 控制资源和费用 | 目录分页、按需读取、有界缓存、隐藏页面暂停轮询，新闻刷新不自动批量调用模型。 |

### 2.2 非功能与排除项

应用首先服务本机环回地址。应具备独立账号、错误反馈、会话过期处理和恢复已有档案的能力，但本机注册不等于面向互联网的生产身份体系。系统不承诺新闻源持续可用，不宣称预测胜率，不提供高频撮合、盘口排队仿真、完整分钟线回放或实盘下单。当前日K播放不能称为逐笔成交回放。

发布材料要能区分开发目录验证和公开发行验证，明确缺失数据的补充方式。源码仓库必须排除有效密钥、账号库、研究库、纸面账户库、个人日志和未获再分发授权的行情。压缩包不能替代比赛要求的GitHub/Gitee仓库，也不能证明完整开发历史；无法恢复的真实Git记录应如实说明，不能回填日期或伪造提交。

## 3 数据基础与证据等级

### 3.1 真实历史日线

当前本机股票目录为3,049只，排除创业板、科创板、北交所及当前名单中的ST、退市标识。三个席位共同读取相同代码、名称和不复权日线。列表只加载小页目录，打开股票时再读取对应文件；每个档案检查身份、单位、日期顺序、OHLC关系、范围与SHA-256。历史预案只看到决策日及以前的记录，后续观察需要单独动作，不能把演示日行情或今天的价格倒灌为历史信号。

当前名单过滤不是完整历史证券状态重建。不复权价格会受到除权、分红及资本事项影响；有真实日线并不意味着历史涨跌停价、停复牌、竞价量和交易日历全部齐全。历史数据下载目标日与实际取得时间分别保存，界面上的历史日期不能自动改成今日。源数据完整性通过文件指纹核对，但指纹不是第三方可信存证或数据授权证明。

### 3.2 巴菲特资料的部分核对

公开财务参考、原文数值证明、严格历史时点核验和人工业务确认使用不同通道。本机当前6只股票、18份年度报告、63项字段具有原文数值证明，状态为`partial_verified`。字段证明保留年报身份、公告时间、PDF页码、单位、换算与原文指纹；读取时检查字段与原PDF，不把一个下载成功标志扩散成全市场已核验。

部分证明可以分别支持利润、ROE和负债等客观条件，却不代表至少三个连续完整年度的全部财务要求、历史更正版本、同期股数与现金流代理都通过。维持性资本开支不以总资本开支、折旧或零值替代；能力圈及护城河不由下载器自动勾选。当前原文核对保持严格时点未通过，完整估值、安全边际和最终买入继续受限。6只样本不是推荐名单，18份报告不是18个独立交易样本。

### 3.3 利弗莫尔资料的分层接入

| 本机只读核对项目 | 2026-11-17准备版本的结果 |
| --- | ---: |
| 可读取的股票档案 | 3,049只 |
| 决策日具备至少120根日线 | 3,035只 |
| 120日区间位置严格低于10% | 816只 |
| 同日价格匹配的来源涨停参考 | 37只 |
| 精确历史限价与当时证券状态 | 0只 |
| 真实个股竞价、指数竞价、区域确认 | 0 / 0 / 0只 |
| 严格候选、执行证据就绪 | 0 / 0只 |

来源涨停池保存请求日期、取得时间和响应指纹，逐股匹配同日不复权日线收盘价。服务器原始`qdate`仅作元数据保留，不作为事件日期。涨停池标注不能证明精确涨停价，未列入池也不能推断已经核验未涨停；涨约10%、分钟高点或全天成交量均不能补造严格字段。37只参考、816只低位股票和最终候选不是同一个集合，不能把任一数量包装成可交易股票数。

严格证据单独读取决策日限价和证券状态，再于入场阶段读取次日9:25个股竞价成交额、指数竞价和事前区域确认。改变次日竞价不能改写前一日冻结信号。当前严格条件不足，全市场只读验收均保持观望，未因此启动模拟账户或调用AI；实时完整退出尚未接齐，利弗莫尔实时新增买入被硬性关闭。

### 3.4 全球新闻与关系证据

新闻来自新浪财经全球市场、中国新闻网国际、美联储及欧洲央行官方公告等白名单公开入口，只取得允许的摘要与元数据，不抓取任意文章全文。后台运行时每300秒检查，保留7日、最多5,000条，页面一次展示40条。显示来源、发布时间、最后成功状态及失败信息；旧缓存不能改标为最新新闻。拒绝、限流或重定向不通过换地址绕过。

位置可以细化到省市，但坐标可能来自地名提取或议题锚点，并非每条消息真实发生地。缺乏可判定位置的新闻仍保留列表，不伪造坐标。关键词候选与主动AI分析分开标识，模型引用原文片段并说明传导假设及不确定性。板块关系和关联股票尚须验证，不能据此声称某公司真实受益或已满足席位规则。

## 4 系统架构设计

### 4.1 分层及主要模块

前端采用Next.js、React和TypeScript，后端为FastAPI与Pydantic，HTTPX负责受约束的外部调用。SQLite分别保存账号、研究档案、模拟账本、新闻缓存和私人新闻AI分析，避免把密码、模型配置和金融记录混在同一用途表内。新闻地球资源随站点同源打包，不依赖运行时CDN。

```text
浏览器：研究台 / 复盘台 / 审计台 / 全球新闻
                         │ 同源 /contest-api
FastAPI：身份会话、请求范围、只读/写入权限
        ├─ 时点证据 → 基础AI或确定性席位 → 独立校验 → 冻结档案
        ├─ 全市场扫描 → 规则预案 → 入场复核 → 虚拟账户与订单
        └─ 新闻白名单 → 有界缓存 → 主动单条AI → 关联与引用
存储：独立SQLite + 有界单股压缩档案 + 指纹索引
```

`historical_seats.py`适配真实历史证据，`paper_market.py`负责目录与行情输入，`paper_engine.py`负责账号隔离和整数分记账。`agent.py`处理基础席位模型协议，`news_ai.py`处理新闻关联；`livermore_data.py`与`buffett_verified.py`分别读取不同证据，不把交易权限交给模型文字。

### 4.2 状态、权限与恢复

账号密码使用独立加盐PBKDF2哈希。登录页提供登录与注册，无默认口令，不提供短信登录、手机号绑定或密码找回。新注册账号不能覆盖旧账号密码或继承其私人记录。身份Cookie、Host及写请求来源检查服务本机环境，仍需要在公网部署前重新评估HTTPS和认证防护。

登录及手动配置的模型会话当前有效期为8小时，Key只保存在后端会话内存，不写浏览器存储、研究档案或公开日志；重启后重新登录及配置。活动单股预案为有界内存对象，至多100条、单条1小时，持久研究档案与模拟订单则保存到本地数据库。已保存记录可以恢复，过期活动预案不能自动获得新的执行权限，未保存的后续结果不会在查看档案时偷偷补算。

切换研究、复盘与审计页面保留同一控制器状态，不重新启用模拟、不重置账户。新规则或新资料影响新研究，不自动重算完成的历史账本。恢复运行保留已处理股票及已保存订单，避免重复成交；服务重启后遗留运行任务改为暂停，操作者确认后再恢复。

## 5 AI技术选型、集成与优化

### 5.1 选型理由及能力边界

项目需要从有限证据生成可检查的条件预案和关联说明，因此采用兼容Chat Completions、工具调用及JSON输出的模型服务，而不是训练端到端自动交易模型。DeepSeek等兼容服务可由使用者选择，实际可用性取决于模型名称、账号权限、额度与协议能力。协议适配不代表不同模型质量等同，不宣称完成训练、微调、名人知识蒸馏、RAG检索系统或自主互联网研究。

真实AI有两个主动入口：基础席位单股研究和单条新闻关联。三账户自主模拟默认执行注册的确定性规则，不对3,049只股票自动批量发送付费模型请求；选定利弗莫尔或巴菲特也不会自动把其规则换成大模型判断。新闻刷新、切页、读取资料卡与复盘播放同样不触发付费模型。

### 5.2 基础席位两阶段协议

第一阶段要求模型唯一调用`get_history_evidence`，参数只能使用本次中性案例ID `sample`。服务端核对工具名、调用数量和参数，拒绝访问其他股票或工具；中性ID减少教学标签对模型的结果暗示。工具返回的是当前股票截止前的白名单证据，后续K线与回放结果不进入模型输入。

第二阶段把工具结果作为协议消息返回，再要求JSON对象。Pydantic校验动作、理由、证据ID、入场上下沿、仓位、保护价和目标价，禁止额外字段、非有限数值或错误类型。引用映射回当前研究对象，无法映射的引用标为未验证。模型可以输出条件模拟或观望，但不能修改规则、执行数据库语句、解除风控或决定成交。

一次完整预案通常涉及两次模型请求；API验证也可能产生最多两次请求，需提示费用。模型失败、超时、工具越权、引用错误或JSON不合格都会明确报错，不静默替换成离线成功。用户可自行改选离线模式，但界面及档案应保留真实调用与离线规则的区别。对话中“API能用”的反馈不构成本项目已留存的逐轮模型实测记录，参赛时须另外保存脱敏调用证据。

### 5.3 新闻AI集成

新闻分析把标题、来源、时间和摘要作为不可信输入，明确禁止把其中的文字当成系统指令。模型只可从服务端允许的板块集合返回关联，包含影响方向、传导原因、原文引用和不确定性。服务端再次检查结构、板块ID和引用片段是否属于本条新闻，不接受模型自造股票买卖动作。无AI结果时仍明确显示关键词候选，不用关键词匹配冒充模型推理。

分析结果按账号、新闻内容指纹、模型及服务地址缓存；新闻内容或模型改变后不复用旧结果。缓存上限为7日且全库最多2,000条，不保存API Key。重新读取新闻可以展示已有结果，不重新调用模型；主动分析一条新闻只发起对应的受控请求，不能从一次点击扩散成全源批量计费。

### 5.4 优化策略与待评估指标

基础研究输入仅包含当前快照，单次输出最多1,000 tokens，不使用流式输出；HTTP超时与28秒分析总时限限制悬挂请求。默认每进程最多20次AI预案尝试，可通过受限环境变量调整，额度在请求前预留，失败也计数。兼容DeepSeek的请求按服务设置关闭额外思考模式，但不改变后端校验。新闻分析输出上限2,400 tokens、响应字节有界，总任务45秒，禁止自动跟随重定向。

这些策略控制输入规模、重复请求和错误放行，不是未经测量的性能提升结论。当前没有模型准确率、选股胜率、跨厂商优劣或长期成本实验。后续应分别测协议成功率、引用有效率、缓存命中、延迟、费用及人工复核负担；Mock协议测试仅验证本系统如何处理响应，不能替代真实模型服务调用记录。

## 6 核心功能实现

### 6.1 研究台：操作和独立账户

主区显示基础、利弗莫尔、巴菲特三个独立账户，各初始100,000元，互不借用现金或合并收益。用户明确启用后，扫描器按代码顺序处理目录，每个席位各自形成买入、卖出、观望或被拦截判断。历史与实时账本分开；历史演示清楚标明决策日与模拟日，不能因今天打开网页而把旧订单改成今日成交。

订单保存股票代码与名称、方向、时间、价格、股数、金额、费用、理由、决策ID及行情来源指纹。持仓保存成本、估值、可卖数量与浮盈亏，账户保存现金及累计结果。一般模拟约束包括100股整手、费用、现金不足、最多5只持仓及T+1；按席位与模式登记的纪律进一步收紧，不能用通用15%分配覆盖利弗莫尔独立预算。资金按整数分记账，避免常见浮点累计误差。

本地历史撮合采用明确标注的开盘价估算，当日收盘仅作估值，不允许当天卖出。盘中模式只使用冻结以后、同日且足够新鲜的报价，不回填早前价格；报价估算不是交易所排队或真实成交证明。缺档、异常OHLC及一字价格会被拒绝；停牌、精确限价等资料按席位独立处理，严格席位不以未知值放行。一般日线估算模型也不因此获得真实执行证明。

### 6.2 两席位的独立门控

利弗莫尔要求至少120根有效历史日线，区间位置严格低于10%，决策日达到来源档案的精确涨停价且历史证券状态合格。入账前独立重读索引档案、重算门槛和冻结参数，不能仅凭外部自报`eligible=true`或伪造低位数字放行。次日执行另验真实竞价、指数与区域条件，合规预算为3,500或5,000元，仍受现金、整手和费用约束；全天成交量不能替代竞价成交额。

该席位真实盘中的Z1涨停顺延一次及跌停后的下一可交易开盘退出尚未形成完整状态机，因此当前在实时新买入口硬性拒绝，不能靠导入竞价资料或前端选项解除。已有持仓仅更新估值并提示限制，不套用通用到期卖出。历史演示也不会因37条来源参考生成严格候选，当前完整执行数量仍为零。

巴菲特按年度财务、持续利润、经营现金流与维持性开支、资本回报、负债、同期股数、能力圈、护城河和保守安全边际逐项检查。客观因素可以单独显示通过，但完整估值和最终买入需要全部必要条件成立。数据下载、原文数值证明与最终交易权限分开，缺资料时保留现金，不把更乐观估值或人工自动确认当成补齐手段。

### 6.3 复盘台：账本统计与日K播放

复盘台读取保存的订单、权益及日快照，显示各席位金额和收益、费用、已实现与未实现盈亏、已平仓胜负、胜率、盈亏因子和权益曲线。胜率分母是可核对的已平仓样本，不把浮盈当作已平仓胜利；缺少完整账本时显示完整性限制，不用有界明细样本替代全量统计。单日演示不年化，也不将日快照回撤冒称完整盘中最大回撤。

每笔保存订单可打开对应真实日K，播放、暂停、前后步进、调速、拖动进度及主动揭示后续均在本地展示层执行。尚未揭示的K线及交易标记不出现在可见图形中；账本统计另按已保存的全量账本计算，不是随播放进度还原的历史时点账户。回放不会创建、重下或修改订单。界面保留时间粒度说明：目前为日线，不是5分钟、15分钟、分时或逐笔数据。

### 6.4 审计台：解释和追溯

审计台以累计判断次数、结果分布、规则与原因样本回答“为什么买、为什么没买”。累计次数来自已保存计数，不把最多若干条明细当成全部决策；缺少计数就保持未知。两席位数据卡在研究与审计主区显示覆盖、严格状态和剩余字段，复盘不重复，也没有读取页面自动启动核验或下单的按钮。

审计同时保留单股工具调用轨迹、引用、独立校验和冻结摘要。SHA-256用于识别内容及规则版本，不是区块链、电子签名或第三方可信时间戳；掌控服务器与数据库的人仍可能改写内容。已完成账本不随后来导入或新模型重算，研究版本变化应创建新记录供比较。

### 6.5 新闻空间与研究记录

左侧新闻列表与可转动地球联动，点击条目转向其坐标；新闻、板块和股票列表按层查看，红绿线和亮度用于表达界面标记的方向与程度，不是收益概率。文字事实、板块传导假设、公司业务关联和席位判断分开说明，避免视觉效果代替证据。

正式实时新闻暂不自动进入固定11月12日的历史研究，防止今日消息污染旧决策。旧情景兼容入口可按服务端登记的新闻、板块、股票及席位关系创建独立草稿，但不能冒充实时研究链。研究档案保存快照、规则指纹、预案、校验及已执行回放，按账号隔离、日期和席位分页，默认每页10条；详情按需打开，新研究不覆盖旧冻结记录。

## 7 技术与应用创新

### 7.1 技术创新点

第一，采用“模型建议—独立规则—执行事实”三层分离。工具权限与JSON约束控制模型输入输出，确定性校验控制是否允许模拟，执行阶段再核验真实资料；即使JSON合法，也不代表满足交易条件。

第二，构建数据证据的分级链。财务参考、原文数值、历史版本和人工业务确认不互相冒充；来源涨停参考、精确限价、历史状态和次日竞价不混为一个成功标志。决策哈希不受下一日执行记录修改影响，而执行证明另存指纹，便于定位输入变化。

第三，将全市场组合账本与单股冻结研究分离。前者回答实际模拟买卖和组合金额，后者回答具体证据及预案，两者共享来源但不混用统计。页面切换只改变视图，不通过重新执行来制造不同结果。

第四，以有界和按需机制约束数据量。行情逐股读取、列表分页、只读覆盖回执、单股指纹缓存、新闻保留期及数量上限共同控制资源；隐藏页暂停轮询，切离新闻释放画布与事件，开场结束释放粒子资源。这里描述的是可检查实现，不宣称已经完成长期内存压力验证。

### 7.2 应用创新点

产品把全球事件观察、规则判断、虚拟金额、未成交原因和复盘结果组织在同一终端，而不是仅给一段选股回答。独立席位让短线和价值风格使用各自证据，保留现金也成为可解释结果。研究、复盘、审计分别对应操作、结果与原因，降低使用者把“看起来合理”误作“已经买入”的风险。

创新定位是本项目的工程组合和可追溯交互，不声称首次提出工具调用、哈希、SQLite、地球可视化或某投资理论，也不以软件测试数量作为金融创新有效性的证明。

## 9 部署、安全与参赛提交

### 9.1 安装及数据准备

建议Python 3.10及以上、Node.js 20.9及以上，项目根目录建立独立虚拟环境，前端使用锁文件安装。后端运行依赖见`requirements.txt`，财报离线提取、文档导出等作者工具依赖另列，不要求网页常驻解析整份PDF。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Push-Location web
npm.cmd ci
npm.cmd run build
Pop-Location
.\.venv\Scripts\python.exe launch.py --production
```

本机入口为`http://127.0.0.1:3001/`，后端监听`127.0.0.1:8001`。已安装并构建后可用随包启动脚本；关闭启动器或重启电脑后需要重新启动，浏览器网址不能自动启动服务。当前无开机自启、服务托管或自动恢复承诺；连接被拒绝时先检查服务进程与端口，不把本机地址当作公网演示链接。

首次进入可注册独立本机账号，选择离线模式或验证自己的模型服务。无模型Key仍能使用本地规则与已有数据，但无真实行情档案时不能演示真实全市场交易：必须按[历史行情使用说明](历史行情使用说明.md)及接入说明准备合法来源数据，设置正确目录并核对日期。源码不暗中下载大批数据，不把空环境替换成虚构股票。外部来源不可用时明确说明，不能承诺评审机器联网即必然获取历史资料。

## 10 总结与展望

当前系统完成真实全市场历史目录、多席位规则、独立虚拟账户、日K复盘统计、决策审计、全球新闻及主动AI关联，并保留有证据边界的基础席位模型研究。核心价值是说明判断依据、执行条件与结果之间的差异，而不是给出未经验证的盈利承诺。

仍需优先补齐授权历史证券状态与竞价、完整财报版本及人工业务证据，完成利弗莫尔实时退出状态机后再评估开放实时新增仓位。其次建立跨时期、样本外、含费用与执行约束的研究，报告失败率和覆盖缺口，而不是用单日演示推断长期收益。新闻与公司产业关系需要独立事实验证；关联解释不替代经济因果研究。

工程方向包括真实模型脱敏实测、持续发行隔离验收、长期内存与并发测量、备份迁移、任务恢复和可选公网防护。新增席位、分钟线和更复杂撮合均按独立证据及测试逐步开放，不把计划写成已完成能力。
