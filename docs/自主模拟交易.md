# 自主模拟交易与交易账本

工作台主区提供基础策略、利弗莫尔、巴菲特三个独立组合，每席位初始虚拟资金100,000元。旧的逐股研究工具保留在默认折叠区，不再把某一只股票当作整个系统的交易账户。

2026-11-17补充：利弗莫尔已接入全市场决策证据和独立入场复核，但本机严格限价/竞价等仍缺，来源涨停参考不放行。完整实时退出状态机未完成，因此实时新增买入硬性关闭，旧仓仅估值。详见[利弗莫尔数据接入验收](利弗莫尔数据接入验收.md)。巴菲特的部分原文数值核对也不解除完整历史版本、估值与人工业务门槛。

## 使用

1. 启动本机正式站并登录，离线模式即可，不需要为自动交易配置模型。
2. 在主区选择“历史演示”或“实时模式”，点一次“启用自动模拟”。不需要逐只选股、逐只生成预案。
3. 研究台负责启用/暂停、扫描进度和三席位资产；复盘台首屏直接进入收益统计与日K回放，再查看订单及持仓；审计台首屏直接进入判断计数、结果分布与未成交原因，不再重复账户资产大卡。
4. 可暂停，账户、订单和持仓不会清空。同一历史日完成后重复启用不会重算收益或重复买入。关闭浏览器不等于停止后端任务；停止启动器、关机或休眠不会继续模拟，服务重启后须重新启用。

没有券商连接、真实下单或自动付费模型调用。这里的“自主”指规则引擎在启用后自主扫描和处理，不是保证每日有交易、保证盈利或已经训练了某位投资者的模型。

复盘台、审计台只保留模式、日期、席位和刷新等查询控件，不显示启用/暂停交易按钮。切换三个台会保留当前账本范围，不重新启动或重算交易。审计概览读取服务器保存的当日累计计数（可包含同股多次判断）；下方原因表仅为有界样本，不能拿样本行数代替全量判断次数。

## 历史演示

模拟交易日为2026-11-13，不能写成打开页面当天的实时报单。按本机已校验沪深主板非ST目录扫描，排除30、688、92开头、ST和退市标识；这是下载时的名单，不是历史成分重建。

所有选股判断只读取11月12日及以前的日线。股票按代码升序处理，**不按次日收益选赢家**。基础席位沿用以决策收盘价为锚的原有入场区间、仓位和保护/目标条件；该规则只是透明的通用价格条件，不声称有预测优势。利弗莫尔仍缺精确涨停和竞价核验时观望，巴菲特仍缺严格时点财报/维持性开支/人工业务确认时观望，不能为展示三条收益曲线而替换规则或强行买入。

满足策略及组合约束的基础预案可按下一交易日真实开盘价作**纸面估算成交**，并注明`historical_open_estimate`等执行标识。这与折叠单股研究的“必须有真实成交证据才放行”不同：它是明确声明假设的模拟模型，不是确认交易所真实成交。缺当日有效日线、零量、一字价格、开盘不在冻结区间等情况不假定成交；不会填造历史涨跌停价或盘口。若使用全天日线作流动性代理，该代理也不是当时盘口或排队证据。

每席位最多5只持仓；单只不超过策略仓位及初始虚拟资金15%的上限，100股整数手，含买入费用不能透支。历史日不能用前一只股票当日收盘后的盈亏给下一只股票加仓。佣金单边0.03%、最低5元，模拟卖出另计0.05%，均为演示假设，不代表实际券商收费。T+1禁止买入当天卖出，11月13日收盘只能更新浮盈亏，不把当天高点或收盘涨幅当成已经卖出的收益。

## 实时模式

只从明确启用之后记录，不补造今天早盘的交易。非连续交易时段只等待；报价必须带同日、严格可解析的时间戳且不过期，不能使用旧报价补单。

每30秒按10只滚动核对本地股票目录，同时观察有界候选与已持仓股票；单次报价最多50只。实时最近日线来自新浪固定公开日线入口，实时报价来自腾讯固定公开行情入口；不接受调用者提供的URL、不读取账户Key、不绕过来源拒绝、限频或重定向。临时连接失败明确等待；401/403/429等拒绝停止任务，不换路径绕过。

新信号只用真实的已收盘日线。最近收盘日期、报价前收和末根收盘不能核对时不下单；当前交易日OHLC不能倒灌到开盘前信号。先冻结候选，再等之后的新鲜有效报价；不会在计算完信号之后倒填当天开盘价。模拟成交采用当时有效买卖报价/最近价并明确标注估算，不保证队列、盘口深度或滑点。原基础策略的退出按收盘条件处理，不能偷偷改为盘中止损；同日买入仍受T+1约束。15:00至15:01:30仅允许核对新鲜的同日15:00收盘报价，估值或按T+1处理旧仓退出，不新建买入；不能在19点用旧收盘报价补单。休市日缺交易日历或报价不合格时宁可不成交。

这是有界滚动扫描，不是全市场逐笔Level-2即时监控。仅持仓和近期候选被每轮持续观察，未轮到的股票不会宣称实时监控。最近日线缓存有界，不把全市场数据和每一条报价永久放进内存。

## 账本与盈亏

订单保存真实证券代码和名称、模拟日期/时点、方向、价格、股数、金额、费用、原因、规则及源数据指纹、撮合假设。完整成交不因界面只显示20条而丢失；历史订单不可通过页面编辑，重复任务有幂等防护。没有交易时明确显示0笔及原因，不塞示例成交。

- 总资产＝可用现金＋持仓估值。
- 累计盈亏＝当前总资产－初始100,000元。
- 当日盈亏＝当前总资产－本模拟日首次启用时冻结的起始权益，含费用。盘中才启用时不是全天市场收益。
- 已实现损益来自已卖出的模拟交易；持仓浮盈亏尚未实现。历史/实时分账，三个席位分账，单股研究也不混入组合收益。
- 查询旧交易日使用保存的当日快照，不用今天价格改写旧日收益。停机期间缺失的时点不会追认成交。

实时持仓按最后有效报价估值，不把它冒称经核验的官方收盘结算；本版未重建分红送转、真实滑点、冲击成本和证券历史状态，收益有这些模型局限。

决策与拒单明细保留每席位每日最多100条有代表性的样本和累计计数，并非每条报价的完整逐笔审计；完整成交账本独立保留。所有列表分页读取，单次订单最多20条、持仓最多15只，不全量载入浏览器。

## 数据隔离与验证

### 复盘台：逐笔订单日K回放

每笔已保存模拟订单可点击“K线回放”，自动定位本账号对应股票和席位；订单下拉仅为前50条快捷项，账本分页上的其他订单仍能通过订单ID选择。图表最多260根真实日K，最多500个同股同席位模拟买卖标记；历史日线使用本机档案及来源指纹，缺少交易日K时明确留空，不把较早日线冒充该笔交易日。

播放器可暂停、逐根前后步进、调速、拖动进度。只绘制当前进度已揭示的日K与该范围内买卖标记，坐标范围也只基于已揭示价格；查看回放不会再执行订单、改写资金或发起模型请求。日K不能恢复一天内高低点的先后顺序，因此这是逐笔订单关联的日K复盘，不是交易所逐笔成交回放。

实时模式从此版启用后，仅为通过原模拟引擎检查的行情保存“每账号、股票、日的最新OHLCV报价快照”，不保存/伪造全日逐笔。快照标明形成中或收盘报价、来源和截至时间，并不冒称官方最终日K。每账号保留30日且最多10,000个日快照，单个股票每天一行、按时间单调更新；没有保存的旧实时K线不追造。已在内存中的真实前序日线可补充上下文，但回放接口不额外访问行情源。

### 完整账本收益统计

统计使用本账号、本模式、所选席位及截止日期的完整已保存订单，不受页面20条分页影响，不把三个账户收益率相加。买卖按FIFO配对并以整数分核算买卖费用；只有已全部平仓的买入批次计为胜、负或持平，未平仓浮盈亏单独显示。

- 胜率＝盈利的已平仓批次 / 全部已平仓批次（包括持平）。没有已平仓样本时留空。
- 盈亏因子＝已平仓盈利金额合计 / 已平仓亏损金额绝对值合计；没有亏损分母时留空，不显示无穷大。
- 展示净损益、费用、买卖次数、胜负/持平数量、平均盈利/亏损、最大单笔已平仓盈利/亏损及持有日历天数。日历天数不冒称持有交易日数。
- 收益曲线来自保存的日快照及当前最新有效估值；单日以起始权益和该日估值两个点展示。界面最多返回起始点及最近365个有效快照，回撤统计仍按完整可用区间计算。
- 最大回撤为日快照曲线的峰谷跌幅，包含起始权益点，不代表完整盘中最大回撤。缺失日不插值，未完成扫描/交易日明确标过程估值，旧日数据不得用今日持仓倒填。
- 数据不足时留空并说明，不用一个模拟日计算年化收益、夏普比率或证明策略有效；出现损坏订单或无法配对的卖出时，已实现损益、完整闭仓数量、胜率及盈亏因子等留空，并提示账本不完整。可核对的闭仓明细仍保留为子集，不把它冒称完整样本，也不把缺失成本算成盈利。

审计和决策状态统一中文显示，例如`position_cap`显示“已达持仓上限”、`already_held`显示“已有持仓”、`price_rejected`显示“价格不符合入场区间”，未知内部状态不直接当英文主表文案展示。

组合默认保存在项目根目录`.paper-accounts.sqlite3`，可用`CONTEST_PAPER_DB`改为已有可写目录内的私有文件。按登录账号哈希、模式、席位分离，不能从请求体指定别人账号、随意重置资金或把实时开始日倒填。GET仅读取账本，开始/暂停必须是登录后的同源POST。数据库、订单、API Key及用户信息不打包公开。

测试使用一次性临时数据库与Mock行情；真实下载档案可在独立测试账户中做全市场端到端验收。演示产生的收益不证明未来可获利，不代替真实成交、策略回测有效性或投资建议。本次更新不修改已封存参赛ZIP/PDF。
