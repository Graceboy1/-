# 巴菲特席位的数据补齐与核验

本轮补齐的是可下载的公开财务参考与原始年报资料，不更改价值策略的阈值，不让“下载完成”自动成为“允许买入”。适用本机现有2026-11-13历史行情档案，决策截止为2026-11-12；完整年度为2023、2024、2025。

## 2026-11-17本机执行结果

- 3049只现有主板股票均取得年度参考，共9147条年度记录；其中3015只的三年四表字段及负债比参考齐全，34只仍有具体缺项，详见 `coverage.json`。
- 原先六只股票的2023—2025年度原始年报共18份，合计68,528,876字节；均核对PDF文件头、文件大小及SHA256，但尚未据此宣称每个财务字段及历史版本已完成核验。
- 每股压缩财务参考合计4,607,645字节，财务索引237,916字节；不将全部报表常驻浏览器。
- 本批严格时点核验通过及策略可用数量仍为0：同期真实股数、维持性资本开支、逐字段原文核验、人工能力圈与护城河尚未齐备。这是保留原纪律，不是通过修改标记来制造交易。

## 公开财务参考

运行 `python tools/download_all_fundamentals.py --dry-run` 只检查本地范围，不联网、不写文件。去掉 `--dry-run` 后，使用东方财富公开年度现金流量表、利润表、资产负债表和年度指标四组数据，按年度分页下载并筛选现有主板非ST目录。排除30、688、92开头、ST及退市标识。

下载采用顺序限速、有界页数与响应大小；遇到401、403、429或重定向立即停止，不绕过限制。源页全部取齐并校验后才写财务缓存。原有完整缓存不覆盖，旧版值不被混成新版本；部分缓存只添加缺失年度。

缓存位于 `data/market-history/2026-11-13/fundamentals/`。每股独立压缩文件及SHA256索引，索引上限6000只、1MB，每股文件上限250KB。页面按股票读取，快捷目录最多40只，不一次把全市场报表送入浏览器。`coverage.json` 保存本次公开参考覆盖数量和逐股缺口，不包含账户、API Key或交易记录。

## 原始年报

运行 `python tools/download_buffett_originals.py --dry-run` 检查计划；正式运行查询巨潮公告元数据并下载原始PDF。默认先保留原来六只参考股票的三年原文，避免无提示下载全市场数千份大PDF。

元数据核对证券代码、完整中文年度报告标题、年度、真实公告日期和公告ID；排除摘要、英文版，版本歧义不擅自选定。文件按公告ID归档，并保留URL、大小和SHA256；原文下载成功不等于其中每个数值、单位、同期股数及重述情况都已核验。

## 不得自动补成真的缺口

- 维持性资本开支：公开现金流量表中的购建长期资产支出是总开支，不直接填入 `maintenance_capex`。
- 同期真实总股数：不能以股本金额当股数，不能用净利润/EPS反推，不能以当前股数填历史年度。
- 历史版本：旧报告期和供应商公告日期不能证明现在下载的每个数字就是当时披露版本，需原文、字段页码、单位和更正记录交叉核验。
- 能力圈：是使用者对生意的理解，不能由系统或企业知名度自动确认。
- 护城河：可搜集品牌、成本、客户留存、转换成本等公开证据，但竞争优势是否持续仍须审阅；不自动勾选通过。

今日作出的人工判断不能倒填为2026-11-12已知的历史判断。当前共享公开缓存也不应保存每个登录用户不同的私人能力圈确认。

## 页面与交易边界

巴菲特财务证据区新增数据清单，分开显示“已下载参考”“待原文核验”“仍缺失”“待人工确认”。字段齐全与是否达到利润、ROE、负债、安全边际门槛是两回事。

未核验参考继续保留 `financial_reports=[]` 和 `point_in_time_verified=false`，不进入严格历史价值决策；未满足全部纪律继续持有现金。本轮不重跑、重置或补造旧模拟订单，不接券商、不发起付费模型请求，不修改已封存参赛ZIP/PDF。

后续接入使用独立原文核对档案：通过原PDF、单位和数值对照的字段，可进入全市场判断并分别展示利润、ROE等客观结果；这不将参考档案整体提升为PIT已核验。历史更正版本和全部必需字段未确认时，仍阻止DCF及最终买入。主区已有接入状态，不必只到单股工具查资料，详见[巴菲特数据接入验收](巴菲特数据接入验收.md)。
