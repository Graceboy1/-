# 巴菲特原文财报接入

## 接入位置

全市场自动模拟通过 `paper_market._plan` → `historical_seats._value_evidence` → `buffett_verified.load_verified` 读取当前股票的原文核对结果。不再只在单股财务参考表里展示。研究台和审计台主区通过同源、已登录的 `GET /paper/dashboard` 显示实际覆盖、原文核对数量、严格时点状态与缺项，不增加开始核验或绕过买入门槛的按钮。

## 两种数据分别使用

1. 东方财富参考档案仍保留原始字段、文件校验和缺失项，不能仅因下载成功进入严格交易。
2. `tools/verify_buffett_originals.py` 离线读取已归档原年报，检查文件指纹、证券及年度身份、公告日期、单位、合并报表语境和当前年度栏，与参考值交叉比较。无法唯一识别、单位不明或金额不符的字段留空。
3. 核对结果独立保存在 `fundamentals/verified/`，每股压缩JSON及SHA256索引；每字段保留原文、PDF实际页码、单位、换算倍率、原始数值、规范数值及原PDF指纹。读取时再次检查归档文件、字段证明、单位换算及负债比计算。
4. 公开参考与原文核对结果均不保存用户的能力圈或护城河确认。缺少维持性资本开支不以总资本开支、折旧或零值替代。

## 逐项判断，不强行买入

三个年度结构、日期、身份合法且对应字段已有核验时，利润、ROE、负债比可以分别显示自身判断结果。缺少人工确认不再将这些客观项目一并抹为失败。

原文数值核对和完整历史时点核验不是同一件事。本轮核对文件的 `point_in_time_verified` 保持false，接入真实档案时明确设置 `require_point_in_time=true`。历史更正版本未核查，或股数、维持性资本开支未齐时，完整财务门槛、DCF、安全边际和最终买入继续被阻断。人工能力圈、护城河也必须单独满足。最终仍要求原有8项全部通过，未降低利润、ROE、负债、安全边际或仓位标准。

## 审计与资源约束

- 每次Buffett预案包含财务证据摘要指纹；原文事实变化会影响新预案指纹，不静默复用旧输入。
- 历史决策只读取严格早于决策日公开的报告，不回填今日人工判断。
- 网页GET不解析整份PDF、不下载数据、不调用模型或生成订单。PDF指纹以分块读取核对，缓存仅存最多32个短指纹，文件时间或大小改变会重新核对。
- 接入概览最多读取20只原文核对档案，主界面最多展示10个摘要；当前参考目录与原文核对目录分开计数，不把部分核验当成全市场已放行。
- 不重跑、重置或覆盖旧模拟订单；不补做财报驱动卖出，也不连接券商。本次不修改已封存参赛ZIP/PDF。

## 运行与验收

2026-11-17本机已用真实公共档案完成一次只读全市场验收：3049只股票均经过新的Buffett判断和财务输入指纹生成；其中6只、18份原年报共63项字段具有已保存的原文数值证明。全部仍保持观望，没有打开账户或创建模拟订单。原文事实部分可让利润、ROE等独立因素显示已满足，但历史更正版本、完整现金流代理及人工业务确认尚未齐备。

代码验收为943项后台测试、184项前端测试及生产构建通过。曾发现并修复跨行股数误取期初、显式旧年度股数表、数值容差未按打印精度收紧等问题，并对实际核对档案执行了原页及精度复查。测试通过不代表价值策略已被回测证明有效，也不代表可以跳过缺失证据。

离线提取工具依赖 `requirements-authoring.txt` 中的pypdf，网页运行不需要安装PDF解析库。支持的实际命令和输出以 `python tools/verify_buffett_originals.py --help` 为准。可使用已配置的文档运行时执行，不向网页进程添加全量PDF常驻缓存。

测试使用临时公共档案和生成数据，覆盖指纹损坏、证券错配、公告同日/未来、单位换算错误、字段缺证据、重复年度、伪造PIT或人工确认、原PDF变化、部分财务因素与最终交易门槛的隔离，以及财务事实变化时预案指纹变化。
